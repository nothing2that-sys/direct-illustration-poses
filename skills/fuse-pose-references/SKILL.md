# 포즈 레퍼런스 융합

목표는 최종 캐릭터 그림이 아니라 **하나로 일관된 새 포즈 레퍼런스**다. 원본 포즈는 https://ai-pose-gallery.pages.dev/ 내부에서만 찾는다. 함께 설치한 direct-illustration-poses의 검색기와 인덱스를 재사용한다. 전체 웹·다른 포즈 사이트로 확장하지 않는다. `<검색스킬>`은 이 스킬과 같은 사용자 스킬 루트에 있는 direct-illustration-poses다.

## 후보 선택과 역할 배정

1. 장면의 행동·감정·지지점·소품 접촉·인원·시점과 인물 기준 좌우를 정리한다. 입력 자세 이미지가 있으면 실제로 열어 특징을 분석한다.
2. 검색 스킬로 후보를 찾고 적합한 2~4개만 선택한다. 각각 미리보기와 원본 PNG를 실제로 연다. 이미지 수집을 위해 검색·다운로드를 반복하지 않는다. 적절한 후보가 하나뿐이면 융합이라고 부르지 않고 그 포즈의 변형 요청으로 구분한다.
3. 한 후보를 base로 정해 몸 전체의 균형·체중·기본 시점을 고정한다. 나머지는 torso, arms, hands, legs, support, camera 중 필요한 역할만 부여한다. 예: A=기본 앉기와 다리 지지, B=턱 괴는 팔과 손, C=상체 기울임. 모든 후보의 전체 자세를 동시에 따라 하게 하지 않는다.
4. 서로 다른 앵글은 출력 카메라 하나에 맞춰 3차원 관계로 해석한다. 관절 가동 범위, 팔꿈치와 무릎의 연결, 발 접지, 손과 소품의 접촉이 충돌하면 기본 자세를 유지하고 충돌하는 보조 특징을 조정한다. 가려진 관절·정확한 좌우는 추정 확정하지 않는다.

## 융합 계획과 참조 준비

작업 폴더에 plan.json을 작성한다. 역할은 중복 배정하지 않으며 base는 정확히 하나다.

```json
{
  "scene": "한쪽 무릎을 세워 앉고, 상체를 조금 숙여 한손으로 뺨을 받친 자세",
  "camera": "정면에서 약간 비스듬한 전신",
  "people": 1,
  "constraints": "팔꿈치는 세운 무릎에 지지. 반대 손과 발로 균형 유지. 인물 좌우를 뒤집지 않음.",
  "references": [
    {"image_id": "실제 검색한 웹 ID A", "file": "실제 원본 PNG 절대 경로 A", "roles": ["base", "legs", "support"], "use": "앉기와 다리의 지지 구조"},
    {"image_id": "실제 검색한 웹 ID B", "file": "실제 원본 PNG 절대 경로 B", "roles": ["arms", "hands"], "use": "턱을 괴는 손과 팔꿈치 연결"}
  ]
}
```

위 ID와 경로는 예시 자리표시자이며 실제 검색 결과와 실제 파일로 바꾼다.

`python "<이 스킬>/scripts/prepare_fusion.py" --plan "<plan.json>" --out "<새폴더>"`

스크립트는 검색 스킬의 갤러리 목록으로 ID를 검증하고 실제 PNG를 복사해 prompt.txt, fusion-manifest.json, imagegen-request.json을 준비한다. `--cache <목록 경로>`도 지원한다. 이미지 시각 검증이나 생성은 자동 수행하지 않는다.

## 새 레퍼런스 생성과 확인

사용 가능한 imagegen 스킬을 읽고 기본 내장 이미지 생성 도구를 사용한다. 실제로 확인한 원본 PNG 전부를 준비된 referenced_image_paths로 전달한다. 캐릭터 얼굴·의상 이미지는 이 단계에 섞지 않는다. 출력은 지정된 인원수의 단순한 무채색 마네킹/해부학 드로잉, 배경 단순, 한 가지 시점, 전신과 지지점이 보이는 이미지 한 장이다. 여러 원본을 나란히 붙인 콜라주나 얼굴·의상 융합 이미지로 대체하지 않는다.

생성 이미지를 실제로 열어 몸통-골반-다리 연결, 어깨-팔꿈치-손 연결, 지지점·무게중심·접지, 손발 수·좌우·인원·시점을 확인한다. 의미 있는 오류가 있으면 필요한 부분만 수정해 다시 확인한다. 해결되지 않은 불확실성은 기록하고 검증이 끝났다고 하지 않는다.

생성 결과를 작업 폴더에 저장하고 fusion-manifest.json에 generated_pose_file, 실제 관찰한 review 결과, 사용한 입력 ID와 역할을 기록한다. 원본 갤러리 이미지와 새로 생성한 레퍼런스를 구분한다. 새 레퍼런스는 generated/synthesized_pose이며 원본 갤러리 ID를 부여하지 않는다. 갤러리 이미지·참조 묶음·개인 경로는 공개 저장소에 올리지 않는다.

## 캐릭터 적용으로 연결

“레퍼런스만 만들어줘”는 여기서 종료하고 결과와 역할별 선택 이유를 보여준다. “이후 캐릭터까지 적용해줘”가 함께 요청되면 중간 결과를 직접 확인한 뒤 create-pose-illustration으로 이어간다. 이미 요청된 작업을 다시 허락받는 단계로 만들지 않는다.

다음 단계에는 **생성한 새 포즈 이미지 한 장 + 캐릭터 기준 이미지 + 융합 manifest**를 전달한다. 새 포즈는 자세·구도, 캐릭터는 얼굴·의상·장비·재질을 담당한다. 원본 후보 전부를 다시 최종 생성에 넣어 역할 충돌을 만들지 않는다. 특정 디테일 보충이 필요하면 그 역할만 명시한다. 중간 생성이 항상 품질을 높인다고 보장하지 않으며 자세 오류와 외형 손실을 각각 점검한다.

생성 도구가 없으면 융합 계획·실제 참조 PNG·프롬프트까지만 반환하고 새 레퍼런스를 생성했다고 하지 않는다. 갤러리 자료가 없거나 조건에 맞지 않으면 다른 사이트로 넘어가지 않고 이유를 알린다. 이미지 없이 자세 설명만 준비한 경우 이미지 융합을 완료했다고 보고하지 않는다.
