# 특징 기반 웹 포즈 검색

검색기는 이미지 인식 모델이 아니다. Codex가 입력 이미지를 실제로 보고 다음 특징을 작업 폴더 JSON에 작성한다. 인물 신원·의상·색·화풍을 자세 검색어로 섞지 않는다. 관찰과 추정 감정, 불확실 부분을 분리한다.

```json
{
  "posture": "바닥에 앉기",
  "torso": "상체 약간 앞으로",
  "arms": "한쪽 팔꿈치를 세운 무릎에 지지",
  "hands": "한손으로 뺨 괴기",
  "legs": "한무릎 세움, 반대 다리 앞으로 뻗기",
  "contact": "반대 손은 바닥 짚기",
  "props": [],
  "people": 1,
  "camera": "정면",
  "mood": "고민하는 장면 후보",
  "uncertain": ["손가락 모양", "인물 기준 좌우"],
  "exclude": ["팔짱"]
}
```

`python "<스킬>/scripts/gallery.py" search --features pose-features.json --limit 5`

텍스트만으로도 같은 검색기를 사용한다.

- `search "의자에 앉아 머리가 복잡한 느낌"`
- `search "기운 없이 축 처진"`
- `search "쪼그려서 턱 괴는 옆모습"`
- `search "바닥에 앉아 무릎을 안고 있는"`
- `search "둘이 포옹" --line pair`

특징 값은 문자열 또는 문자열 목록이며 people은 1/2만 허용한다. uncertain은 점수화하지 않는다. camera는 명시적인 --angle보다 우선하지 않는다. 사람 수는 --line보다 우선하지 않는다. 필터 결과가 없으면 인원·소품·시점을 조용히 바꾸지 않는다.

현재 검색은 AI Pose Gallery 이름/분류로부터 만든 규칙 기반 개념 매칭이다. 외부 API·임베딩 비용은 없다. 동의어·공백 차이를 지원하지만 임의의 모든 문장이나 이미지 유사도를 이해한다고 보장하지 않는다. source 이름에서 연결한 감정·장면 후보는 관찰 확정이 아니다. 지원되지 않는 동작도 전체 웹 검색으로 확장하지 않는다. 같은 갤러리 안의 가까운 후보와 차이를 알리거나 자료가 없다고 반환한다.

검색은 ID·일치/누락만 간결하게 출력하고 선택한 ID의 show에서 URL을 제공한다. --details는 검색 결과에 URL까지 포함한다. 동일 포즈의 여러 앵글은 한 후보로 묶으므로 후보 다양성을 확보한다. 최종 선택 시 웹 원본을 열어 손·몸통·무릎·접지·시점을 확인해야 한다.
