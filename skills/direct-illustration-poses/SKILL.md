# 삽화 포즈 디렉터

기본 검색원은 https://ai-pose-gallery.pages.dev/ 이지만 유일한 공급원은 아니다. 개인 Drive나 특정 PC 경로가 필요하지 않다. `scripts/gallery.py`는 Python 3.10 이상 표준 라이브러리를 사용한다. 명령의 `<스킬>`은 실제 로드한 SKILL.md의 부모 경로다.

## 장면 분석과 참조 경로 선택

행동·감정·소품·인원·시점·인물 기준 좌우를 정리한다. 캐릭터 기준 이미지 또는 편집 대상이 실제 사람 사진인지, 동상·그림인지, 허구 캐릭터인지 구분한다. 외형·의상·장비·재질 등 보존할 요소와 가정을 적는다.

자료 출처의 이용 조건과 생성 도구의 제한을 구분한다. 특정 갤러리 자료를 사용할 수 없다는 이유로 편집 작업 전체를 거절하거나, 생성 도구가 차단했다고 말하지 않는다. 역사적 인물의 동상 등을 해당 사이트의 예외라고 임의로 단정하지도 않는다. 다음 순서로 요청 범위 안에서 계속 진행한다.

1. **갤러리 이미지:** 용도가 [출처 이용 범위](references/source-and-terms.md)에 맞으면 아래 갤러리 검색 흐름을 사용한다.
2. **다른 허용된 이미지:** 갤러리 조건이 맞지 않거나 접근 실패·검색 결과 불일치·이미지 전달 실패가 있으면 사용자가 제공한 로컬/Drive 포즈, 직접 제작한 자세 자료, 해당 용도를 허용하는 공개 자료를 검토한다. 외부 자료는 원본 페이지에서 라이선스·사용 범위를 확인하고 실제 선택 이미지를 연다. 공개 인터넷 자료를 검색할 도구가 있으면 적합한 출처를 한 번 검색하고 유력한 후보를 확인한다. 허용된 대안을 찾지 못하면 자료 탐색을 반복하며 작업을 멈추지 말고 다음 단계로 간다. Drive에 옮기는 것만으로 원래 이용 조건이 없어지는 것은 아니다.
3. **자세 설명:** 적합한 이미지가 없으면 일반적인 자세·해부학·구도 설명으로 진행한다. 갤러리 이미지를 사용하지 않았고 포즈 이미지 참조 없이 진행한다고 짧게 알린다. 편집 대상·캐릭터 기준 이미지는 계속 실제 파일로 전달한다. 예: 나무 자세는 지지 다리, 반대 발을 놓을 허벅지 또는 종아리 위치(무릎 관절은 피함), 모은 두 손, 균형축과 카메라를 구체화한다. 칼·장비 처리나 인물 좌우를 임의로 바꾸지 말고 보존·요청 조건을 명시한다.

출처나 인물을 숨겨 도구의 판단을 속이지 않는다. 생성 도구 자체가 요청을 거절하면 거절 이유를 정확히 알리고 허용되는 수정으로 대응한다. 출처 제한은 그 자료에만 적용하며 다른 자료·자세 설명 사용을 금지하는 일반 규칙으로 확장하지 않는다.

## 갤러리 검색과 이미지 확인

`python "<스킬>/scripts/gallery.py" search "앉아서 고민" --line standard --angle front --limit 6`

첫 실행은 사이트 HTML 한 건의 텍스트 목록만 읽어 로컬 캐시에 저장하며 이미지를 수집하지 않는다. 한국어·영어 키워드를 일본어로 확장하되 감정·소품·자세의 완전한 일치를 보장하지 않는다. `--refresh`는 명령 앞에 붙여 갱신한다. 정확한 ID가 있으면 `show <ID>`로 조회한다.

브라우저의 검색창에 결과 ID/일본어 이름을 입력해 분류·앵글을 확인한다. 미리보기를 실제 이미지로 연 뒤 후보를 선택한다. 로컬 파일이 필요하면 `fetch <ID> --kind preview --out <작업폴더/preview.jpg>`로 후보 한 장만 받는다. 선택 후 `fetch <ID> --kind original --out <작업폴더/pose.png>`로 원본 한 장만 받고 실제로 연다. 미리보기는 선택용이며 생성에는 원본을 전달한다.

검색 결과·파일 존재만으로 시각 확인 완료라 하지 않는다. 자세·시점·인원·손·관절·접촉·접지를 확인하고, 바닥앉기와 의자앉기처럼 다른 조건은 명시한다. 이미지 일괄 다운로드·미러링·재배포를 하지 않는다. 접근 차단이나 구조 변경 시 URL을 추측해 우회하지 않고 다른 자료/자세 설명 경로로 전환한다.

## 참조 준비

캐릭터·편집 대상은 외형·의상·장비·재질을, 포즈 이미지는 자세·구도만 담당한다. 실제 입력 이미지를 모두 열어 보고 인물 기준 좌우와 화면 좌우를 구분한다. 사용자 요청 없는 반전을 피한다.

갤러리 원본:
`python "<스킬>/scripts/gallery.py" prepare --pose-file <pose.png> --pose-id <ID> --scene "<장면>" --character <캐릭터.png> --out <새폴더>`

외부 허용 자료(이미지는 연결 도구/브라우저로 내려받은 뒤 열어 확인):
`prepare --pose-file <pose.jpg> --pose-source external --source-url <원본페이지> --rights-note "<확인한 허락·용도>" --scene "<장면>" --character <캐릭터.png> --out <새폴더>`

사용자 제공 로컬/Drive 자료는 `--pose-source user`로 표시한다. Drive 읽기 도구가 없거나 연결이 끊겼어도 일반 자세로 진행 가능한 요청이면 설명 경로로 이어간다. 사용자가 특정 포즈 이미지와의 정확한 일치를 요구한 경우에는 파일 확보가 필요하다고 설명하며 대체 설명을 동일한 결과라고 보장하지 않는다.

자세 설명만 사용:
`prepare --pose-description "<관절·지지점·손발·시점 설명>" --fallback-reason "<갤러리를 사용하지 않은 이유>" --scene "<장면>" --character <편집대상.png> --constraints "<좌우·외형·재질 보존 조건>" --out <새폴더>`

`--character`는 반복할 수 있다. 출력은 prompt.txt, reference-manifest.json, imagegen-request.json과 실제 선택 파일의 로컬 복사본이다. manifest의 `reference_mode`는 gallery_image / external_image / user_image / description_only를 구분한다. 설명 경로에는 포즈 이미지·갤러리 ID·가짜 파일 경로를 넣지 않으며 `referenced_image_paths`에는 실제 캐릭터·편집 대상만 들어간다. 캐릭터 자료가 없으면 `needs_character_reference`로 표시한다. 시각 확인은 자동 수행하지 않으므로 실제 열람 결과를 별도로 기록한다. 출력의 개인 경로와 참조 이미지는 공개 저장소에 커밋하지 않는다.

## 생성과 결과 보고

사용자가 생성·편집을 요청했고 도구가 있으면 선택한 경로의 prompt와 실제 참조파일을 전달한다. 자세 설명 경로에서는 포즈 파일이 없어도 이미 제공된 편집 대상과 자세 설명으로 계속 진행한다. 필수 편집 대상 자체를 보낼 수 없는 경우에는 누락을 알린다. 도구가 없으면 파일과 프롬프트를 반환한다. 설치·검색·참조 준비만 요청받으면 새 삽화를 만들지 않는다.

어떤 출처/설명 경로를 썼는지, 실제로 열고 전달한 이미지, 보존 요소·좌우, 다른 조건과 미확인 사항을 짧게 보고한다. 설명 경로의 결과를 갤러리 포즈 참조 결과라고 표현하지 않는다.
