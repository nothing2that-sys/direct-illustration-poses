# 삽화 포즈 디렉터

웹의 포즈 이미지를 찾는 것이 기본 역할이다. 기본 검색원은 https://ai-pose-gallery.pages.dev/ 이다. Python 3.10 이상 표준 라이브러리만 사용한다. 아래 <스킬>은 실제 로드한 SKILL.md의 부모 경로다.

## 요청과 자세 분석

- “찾아줘·추천해줘·비슷한 포즈”는 후보 확인과 안내까지 수행한다.
- “그려줘·생성해줘·이 이미지의 자세를 바꿔줘”는 검색과 시각 확인 후 실제 참조파일을 생성 도구에 전달한다. 이미 생성이 요청되었다면 다시 허락을 묻지 않는다.
- “참조 준비까지만”은 파일과 프롬프트 준비에서 끝낸다.

텍스트가 모호하면 감정을 구체적인 자세 후보로 해석한다. 예: “머리가 복잡한” → 턱·뺨 괴기 또는 머리에 손, “기운 없이 축 처진” → 상체 숙임·늘어진 팔. 이 해석은 확정된 감정이나 이미지 관찰 결과와 구분한다.

입력 이미지가 있으면 먼저 실제로 연다. 얼굴·의상·화풍보다 지지점, 앉기/서기/눕기, 몸통 기울기·회전, 팔꿈치·손 위치, 무릎·발 방향, 접촉, 인원, 카메라 높이를 분석한다. 가려진 관절과 좌우가 애매한 부분은 불확실로 남긴다. 캐릭터 외형 참조인지, 찾을 자세의 예시인지, 편집 대상인지 구분한다. 이미지 파일을 검색 스크립트에 넣었다고 시각 검색한 것으로 표현하지 않는다. Codex가 이미지를 관찰해 특징을 작성하고 스크립트가 웹 텍스트 목록에서 후보를 찾는 방식이다. 특징 형식과 예시는 [검색 안내](references/advanced-search.md)를 참고한다.

## 웹 후보 검색

`python "<스킬>/scripts/gallery.py" search "앉아서 머리가 복잡한 느낌" --limit 5`

입력 이미지를 관찰한 특징 파일이 있으면:
`python "<스킬>/scripts/gallery.py" search --features "<작업폴더>/pose-features.json" --limit 5`

처음에는 웹 HTML의 텍스트 목록 한 건을 캐시하며 이미지를 받지 않는다. 한글·영어 표현을 자세 개념과 일본어 원본 이름에 연결해 복합 특징을 점수화한다. 검색 결과는 같은 포즈를 묶어 상위 5개 ID·이름·일치/누락 특징만 출력한다. 전체 목록이나 검색기 소스를 매번 모델 문맥에 읽지 않는다. `show <ID>`에서 선택 후보의 미리보기·원본 URL을 얻는다. 명령 앞의 `--refresh`로 웹 목록을 갱신한다.

기본 분류는 표준 전신 1명이다. 상반신은 `--line upper`, 2인은 `--line pair`를 사용한다. 성적 표현 분류는 사용자가 해당 맥락을 요청한 경우에만 `--line sexy`로 지정한다. `--angle front/high/low/side/diag`, `--exclude "팔짱"`을 지원한다. 카메라 표현과 두 사람 요청은 자동 필터에도 반영된다. 필터·분류는 최종 이미지와 대조한다.

`matched`는 웹 이름·분류 메타데이터의 일치이며 시각 검증이 아니다. `missing`은 아직 뒷받침되지 않는 요청 조건이다. 의자·검·걷기처럼 목록에 없는 조건을 만족했다고 하지 않는다. 결과가 없거나 누락이 크면 핵심 자세로 검색을 한 번 넓히고, 웹 검색 도구로 다른 적합한 공개 포즈 출처도 확인한다. 일반적인 대체 후보라면 차이를 설명한다. 일치하는 자료가 없을 때 자세 설명만으로 진행했다는 사실을 밝힌다.

## 실제 이미지 확인과 반환

[출처 조건](references/source-and-terms.md)을 확인한다. 선택 후보 한 장씩만 가져온다.
`python "<스킬>/scripts/gallery.py" fetch <ID> --kind preview --out "<작업폴더>/preview.jpg"`
미리보기를 실제로 열어 후보를 고른 뒤:
`python "<스킬>/scripts/gallery.py" fetch <ID> --kind original --out "<작업폴더>/pose.png"`

원본도 실제로 열고 자세·접지·손·인원·소품·시점을 확인한다. 입력 이미지가 있으면 몸통·팔다리·지지점·시점의 유사점과 차이를 비교한다. 이미지 URL을 검색 결과로 얻거나 파일이 존재하는 것만으로 “이미지 확인”이라 하지 않는다.

검색 요청에는 확인한 후보 1~3개의 짧은 설명과 출처 링크를 반환한다. 도구가 허용하면 실제로 연 이미지를 미리 보여준다. 정확히 일치하지 않는 조건과 미확인 부분을 적는다. 이미지 전체 수집·미러링·공개 재배포는 하지 않는다.

## 참조 준비와 생성

캐릭터/편집 대상은 얼굴·외형·의상·장비·재질을, 포즈 이미지는 자세·구도를 담당한다. 실제 입력 파일을 모두 열어 보고 작품의 인물 기준 좌우와 화면 좌우를 구분한다. 사용자 요청 없는 반전을 피한다. 기준 인물이 없는 일반 삽화는 요청된 외형과 장면 설명으로 디자인하며 캐릭터 자료를 불필요하게 요구하지 않는다.

`python "<스킬>/scripts/gallery.py" prepare --pose-file "<pose.png>" --pose-id <ID> --scene "<장면>" --character "<캐릭터.png>" --constraints "<좌우·설정·보존 조건>" --out "<새폴더>"`

캐릭터 파일이 있을 때만 `--character`를 사용하며 여러 번 지정할 수 있다. 결과는 prompt.txt, reference-manifest.json, imagegen-request.json과 실제 파일 복사본이다. prepare는 생성이나 시각 확인을 자동 수행하지 않는다. 캐릭터 미제공 상태는 특정 외형 보존의 미확정 표시이며 일반 이미지 생성 요청 전체를 막는 조건이 아니다.

생성 요청이면 imagegen 스킬을 사용하고, 준비한 프롬프트와 실제 선택 PNG·캐릭터/편집 대상의 로컬 파일 경로를 참조 입력으로 전달한다. URL이나 설명만 전달한 것을 이미지 참조라고 보고하지 않는다. 생성 후 포즈·인원·소품 접촉·좌우와 외형 보존을 확인하고 결과를 보여준다. 생성 도구가 지원되지 않으면 참조파일과 생성용 프롬프트를 반환한다.

## 출처 실패와 대안

특정 출처의 조건이 맞지 않거나 접근/전달이 실패하면 용도를 허용하는 다른 웹 자료를 찾고 실제 선택 이미지를 확인한다. 외부 원본 페이지와 이용 범위를 기록하며 prepare에 `--pose-source external --source-url <페이지> --rights-note "<확인한 범위>"`를 사용한다.

적합한 이미지가 없으면 `prepare --pose-description "<지지점·관절·시점 설명>" --fallback-reason "<사유>" ...`로 준비한다. 이 경우 포즈 이미지가 없음을 밝히고 캐릭터/편집 대상 파일은 계속 실제 입력으로 전달한다. 원래 작업의 정확한 이미지 일치가 필수라면 그 한계를 알린다. 출처의 조건을 생성 도구 전체의 제한으로 확대하지 않고, 출처·인물을 숨겨 판단을 속이지 않는다. 생성 도구가 거절하면 실제 사유와 허용되는 수정으로 대응한다.
